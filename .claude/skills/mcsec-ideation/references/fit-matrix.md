# جدول تطابق: WHMCS، موتورها، ماژول‌های مارال، زمینه‌ی ایران

برای گام ۴ اسکیل. هر ادعایی که این‌جا منبع ندارد ⚠ است و پیش از ساختن روی staging سنجیده می‌شود.

## ۱. WHMCS خودش چه دارد (اول همین را به کار ببر)
| امکان WHMCS | MC-Sec با آن چه می‌کند | یادداشت |
| --- | --- | --- |
| محصول و ماژول provisioning | پلن = محصول روی `modules/servers/mcsec` (`CreateAccount`، `Renew`، `ChangePackage`…)، فقط پایگاه داده | سبد، تسویه، تمدید و تعلیق مال WHMCS است؛ دوباره نساز |
| فاکتور و درگاه پرداخت | بسته‌ی اعتبار = فاکتور WHMCS؛ اعتبار با هوک `InvoicePaid` و ref یکتا | درگاه‌های داخلی ایران از قبل در WHMCS مارال هستند |
| گروه مشتری | اعتبار رایگان ماهانه و سقف دارایی برای هر گروه (`group_rules`) | — |
| دامنه‌ها و سرویس‌های حساب | تأیید خودکار `whmcs` (`Verify::instant`) | فقط خواندن |
| کاربر و مجوزهای حساب | هویت از نشست؛ کاربر غیرمالک با مجوز همان حساب | نقش ریزتر = MC-Team (X19) |
| ایمیل (`SendEmail`) | اعلان ایمیلی با قالب عمومی | `noemail` هرگز |
| تیکت | «از پشتیبانی بخواه» با تیکت پرشده | ⚠ `OpenTicket` از طرف مشتری را روی staging بسنج |
| cron (`AfterCronJob`) | کار پس‌زمینه با قفل | هوک صفحه هرگز به شبکه وصل نمی‌شود (`whmcs-addon` §۲) |

## ۲. موتورها: توان و مرز
| موتور | خوب برای | مرز و هزینه | منبع |
| --- | --- | --- | --- |
| داخلی (`Builtin`) | TLS، هدر، کوکی، فایل‌های شناخته‌شده، SPF و DMARC، CAA، درگاه پرخطر روی IP خود مشتری | سبک و رایگان؛ بی اکسپلویت | `lib/Engines/Builtin.php` |
| OASM (v0.12.1) | کشف زیردامنه، درگاه، سرویس، فناوری، TLS؛ nuclei؛ connectorهای wpscan، ZAP، Nikto | هر کاربر حداکثر ۵ فضای کار (یک کاربر OASM برای هر مشتری)؛ کشف خودکار محدوده را گسترش می‌دهد؛ `interactsh` عمومی؛ بازه‌ی `/24` صدها کار | `docs/research/oasm-api.md` §۸ |
| Osmedeus (v5) | جریان‌های شناسایی و ارزیابی (`fast`، `general`، `cidr`، `url`) | بی صف سمت سرور، SQLite، اجرای چندساعته؛ `enum-ipspace` و `probe-port` در جریان دامنه | `docs/research/osmedeus-api.md` §۸ و §۱۴ |
| مدل AI (سازگار با OpenAI) | گزارش و راهکار فارسی | هزینه‌ی توکن با اعتبار؛ ماسک داده‌ی شخصی؛ خروجی صفحه‌ی اسکن‌شده داده است، نه دستور | `lib/Ai.php` |

## ۳. ماژول‌های مارال: صاحب هر داده
| داده | صاحب | MC-Sec |
| --- | --- | --- |
| حساب، کاربر، سرویس، دامنه، فاکتور، تیکت | WHMCS | فقط خواندن؛ نوشتن فقط با `localAPI` و در مسیر مجاز |
| دارایی، تأیید، اسکن، یافته، سطح حمله، گزارش، زمان‌بندی، اعتبار اسکن، اعلان امنیتی | **MC-Sec** | صاحب |
| رابطه با مشتری، پیگیری، پیام تبلیغاتی، فرصت فروش | MC-Care | فقط رویداد از پل می‌فرستد (X8) |
| سازمان، تیم، نقش، دعوت | MC-Team | از قرارداد پل می‌خواند (X19) |
| حساب و مصرف هوش مصنوعی | MC-AI | ⚠ اگر بودجه‌ی AI یکی شود، از قرارداد |
| گفتگو با مشتری (سایت، بات) | رایا | — |

قاعده‌ها (قرارداد پل مارال): هیچ ماژولی جدول ماژول دیگر را نمی‌خواند یا نمی‌نویسد؛ هر ماژول بی دیگری کامل کار می‌کند؛ اتصال فقط با `mod_maral_bridge_events` و hookهای مستند؛ هرگز دو نسخه از یک واقعیت.

**این ایده کجا ساخته شود؟** اسکن، یافته، امتیاز، اعتبار اسکن ⇐ MC-Sec. پیام فروش یا پیگیری انسانی ⇐ MC-Care. نقش و دسترسی تیمی ⇐ MC-Team. پرداخت و تمدید ⇐ WHMCS.

## ۴. زمینه‌ی ایران
| موضوع | واقعیت | پیامد |
| --- | --- | --- |
| تحریم | فروشنده‌ها و APIهای پولی غربی (Shodan، Censys، API تجاری زیردامنه) در دسترس یا قابل پرداخت نیستند | منابع خودمیزبان و رایگان؛ mirror داخلی قالب‌های nuclei |
| پیام‌رسان | تلگرام فیلتر است و سرور داخلی شاید به API آن نرسد؛ بله API شبیه تلگرام دارد | بله کانال اصلی؛ تلگرام اختیاری؛ سلامت کانال در پنل مدیر |
| پرداخت | فقط درگاه‌های داخلی، از راه فاکتور WHMCS | هیچ پرداخت مستقیم در ماژول |
| فرهنگ خرید | «بسته‌ی یک‌باره + پشتیبانی» آشناتر از اشتراک ماهانه | بسته‌ی اعتبار، پرداخت سالانه، پل به خدمت انسانی (Y1) |
| قانون | قانون جرایم رایانه‌ای؛ نهادهای دولتی زیر نظر افتا | قواعد درگیری `cybersec-expert`؛ هیچ ادعای «گواهی» |
| شاپرک و اینماد | تطابق دامنه و IP ثبت‌شده‌ی پذیرنده | چک‌لیست «آمادگی درگاه» (X17) |
| زبان | هیچ رقیب گزارش فارسی ندارد | گزارش AI فارسی مزیت اصلی است؛ کیفیت فارسی را جدی بگیر |
