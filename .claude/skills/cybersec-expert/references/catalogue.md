# کاتالوگ یافته‌های رایج مشتری هاست

شدت پیش‌فرض MC-Sec برای یافته‌هایی که بیشتر از همه روی سایت‌ها و سرورهای مشتریان مارال دیده می‌شوند، با دلیل، نگاشت و روش سنجیدن رفع. **کلید** همان کلید پایگاه دانش (`kb`) است که موتورها به آن نگاشت می‌شوند (`Findings::ingest`، `Kb::match`)؛ اگر کلیدی در کد نیست، این‌جا پیشنهاد است.

قاعده‌های خواندن جدول:
- «شدت پیش‌فرض» برای سایت عمومی روی اینترنت است. ستون «بالا یا پایین» می‌گوید کی عوضش کنی. اگر شدت موتور را عوض کردی، شدت اصلی موتور و دلیل در شواهد بماند (شفافیت).
- ستون OWASP **نزدیک‌ترین دسته** است (2021 → 2025)، نه لزوماً فهرست رسمی CWEهای آن دسته. فهرست رسمی: https://owasp.org/Top10/ و https://owasp.org/Top10/2025/
- «—» یعنی نگاشت دقیق وجود ندارد؛ نگاشت ساختگی ننویس.
- «رفع را چطور می‌سنجیم» همان چیزی است که بررسی مجدد (retest) باید ببیند تا یافته `fixed` شود.

## ۸. بازنگاشت خروجی موتورها
| خروجی | رفتار در MC-Sec |
| --- | --- |
| nuclei با شدت `info` و برچسب `tech` یا قالب‌های `*-detect` (`http/technologies/`) | سطح حمله (فناوری)، نه یافته؛ در شمارش و امتیاز نمی‌آید |
| `http-missing-security-headers:<هدر>` | هر هدر به کلید خودش (`hsts-missing`، `csp-missing`…)، حداکثر پایین، در رابط با «گروه‌بندی بر اساس مشکل» |
| قالب‌های `ssl/` اطلاعاتی (نام‌ها، صادرکننده، نسخه) | سطح حمله (گواهی) |
| `http/exposed-panels/` | `panel-exposed` فقط برای ابزار مدیریتی؛ بقیه سطح حمله |
| `http/default-logins/` | `default-login` |
| `http/takeovers/` | `takeover` |
| `http/exposures/` و بکاپ و پیکربندی | `web-env` و `web-backup`، فقط با الگوی محتوای مشخص (نه فقط وضعیت 200) |
| قالب CVE که فقط رشته‌ی نسخه را می‌خواند | اعتماد «احتمالی» و سقف متوسط تا اثبات رفتاری |
| شدت ناشناخته یا `unknown` یا SARIF | `Findings::severity` (پیش‌فرض اطلاعاتی) و بازبینی دستی نگاشت |
