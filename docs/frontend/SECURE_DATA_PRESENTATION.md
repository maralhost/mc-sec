# نمایش امن داده‌ی غیرقابل‌اعتماد

هر چیزی که از اسکنر، سرویس بیرونی، سایت مشتری یا خود مشتری می‌آید غیرقابل‌اعتماد است: عنوان و شرح یافته، شاهد (evidence)، سرآیند و بنر سرویس، نشانی، خروجی ابزار، نام میزبان، عنوان صفحه، متن مدل هوش مصنوعی، نام کاربر. معتبر بودن نام ابزار دلیل اعتماد به خروجی‌اش نیست.

## قاعده‌ها و جای اجرایشان

| خطر | قاعده | کجا |
| --- | --- | --- |
| XSS ذخیره‌شده و بازتابی | هر مقدار پویا از `Ui::e()` / `Text::e()` می‌گذرد. HTML هیچ یافته‌ای اجرا نمی‌شود. | همه‌ی `lib/Client/*` و `lib/Admin/*` |
| اسکریپت در JS | در `client.js` فقط `textContent`؛ هرگز `innerHTML` با داده | `client.js` |
| شاهد، سرآیند، خروجی ابزار | فقط به‌صورت متن در بلوک کد (`Ui::code`)، چپ‌به‌راست، با سقف طول | `FindingViews`، `ReportViews` |
| پیوند خطرناک | پیوند بیرونی فقط `http(s)://`، با `rel="noopener"` (منبع‌های اسکنر و مدل: `noopener noreferrer`)؛ `javascript:` و `data:` هرگز پیوند نمی‌شوند | `FindingViews` (منبع‌ها، پیشنهاد خدمت) |
| متن چندخطی | `Ui::para()` (escape و سپس شکستن خط) | یافته و گزارش |
| توکن فنی | `Ui::ltr()`: جدا از متن، چپ‌به‌راست، escape‌شده | دامنه، IP، درگاه، CVE، هش |
| تزریق فرمول در CSV | سلولی که با `= + - @` شروع شود آپاستروف می‌گیرد | `Findings::csv` |
| تصویر از منبع بیرونی | اسکرین‌شات فقط از مسیر ذخیره‌ی خود OASM کپی می‌شود، نوعش از روی بایت‌ها شناخته می‌شود (JPEG/PNG)، سقف اندازه دارد، و فقط به صاحب همان حساب با `nosniff` و CSP بسته داده می‌شود | `Shots`، `Controller::file` |
| پیش‌نمایش HTML بیرونی | نداریم و بی تأیید جدا ساخته نمی‌شود | |
| افشای رمز | رمز، کلید و توکن رمزنگاری‌شده می‌مانند و هرگز نمایش یا لاگ نمی‌شوند؛ داده‌ی اسکن پیش از رفتن به مدل پاک و ماسک می‌شود | `Crypto`، `Trace::scrub`، `Ai::clean`/`mask` |
| داده‌ی حساب دیگر | هر گزارش، یافته، اسکن، دارایی و فایل با حساب نشست خوانده می‌شود | `Assets::get`، `Scans::get`، `Findings::get`، `Reports::get` |
| فایل گزارش و شاهد | PDF، CSV و تصویر فقط از `Controller::file` و پس از سنجش حساب؛ پیوند اشتراکی فقط همان یک گزارش را نشان می‌دهد | `Controller`، `Shares` |
| متن مدل | فقط escape‌شده نمایش داده می‌شود؛ هیچ عدد امنیتی از مدل نمی‌آید | `AssistantViews`، `ReportViews`، `SetupAdvisor` |

## برای هر کامپوننت تازه

1. ورودی کامپوننت را «متن» فرض کنید. اگر کامپوننتی HTML آماده می‌گیرد (مثل بدنه‌ی `Ui::card`)، سازنده‌ی آن HTML مسئول escape است و این باید در امضای تابع روشن باشد.
2. آزمون XSS با `<script>alert(9)</script>` برای هر مقدار تازه‌ای که از بیرون می‌آید.
3. پیوند ساخته‌شده از داده: فقط `http(s)`، وگرنه متن ساده.
4. مقدار فنی: `Ui::ltr()`؛ هرگز RTL اجباری روی IP، دامنه، URL، CVE، هش یا خروجی دستور.
5. کتابخانه‌ی نمودار یا جدول آینده: tooltip و برچسب باید متن بگیرند، نه HTML. این شرط پذیرش است.

استانداردسازی ظاهر هرگز دلیل برداشتن یا سست کردن یکی از این قاعده‌ها نیست؛ آزمون‌های امنیتی موجود برای جور شدن با ظاهر تازه حذف یا ضعیف نمی‌شوند.
