# رابط کاربری تحلیل امنیتی

الگوهای نمایش داده و گردش کار امنیتی MC-Sec. از محصول‌هایی مثل Tenable، Qualys، Rapid7 InsightVM، Microsoft Defender، Wiz، Snyk و SecurityScorecard فقط **الگو** گرفته می‌شود (چه چیزی کنار چه چیزی، چه ترتیبی)؛ ظاهر، متن و دارایی اختصاصی هیچ‌کدام کپی نمی‌شود.

**قاعده‌ی اصلی: هیچ شاخص، امتیاز یا داده‌ی ساختگی در رابط کاربری نمی‌آید.** چیزی که در Backend نیست فقط در نقشه‌ی راه ثبت می‌شود.

## چهار مفهوم که نباید یکی نشان داده شوند

| مفهوم | یعنی چه | از کجا | نمایش |
| --- | --- | --- | --- |
| **شدت یافته** (Severity) | خود مشکل چقدر بد است | اسکنر، نرمال‌شده در `Findings::severity` | `Ui::sev`: شکل + واژه + رنگ؛ توکن `--mds-sev-*` |
| **اولویت یافته** (Priority، ۰–۱۰۰) | الان کدام را اول رفع کنم | `Intel::priority`: شدت/CVSS × EPSS × KEV | عدد «از ۱۰۰» و ترتیب فهرست |
| **احتمال بهره‌برداری** | EPSS (احتمال در ۳۰ روز) و KEV (همین حالا بهره‌برداری می‌شود) | FIRST EPSS، CISA KEV | درصد EPSS؛ نشان «در حال بهره‌برداری» |
| **امتیاز امنیت دارایی/حساب** (۰–۱۰۰، بیشتر بهتر) | وضعیت کلی | `Score`، قطعی، با سقف (بحرانی یا KEV باز ← ۴۹، بالا ← ۷۹) | حلقه با رتبه‌ی A تا F؛ توکن `--mds-risk-*` |
| **وضعیت رفع** | باز، رفع‌شده، ریسک پذیرفته، مثبت کاذب | چرخه‌ی عمر یافته | `chip`؛ «رفع‌شده» را فقط سامانه می‌زند |

الگوریتم هیچ‌کدام (امتیاز، شدت، اولویت) بی تأیید جدای بنیان‌گذار عوض نمی‌شود. رابط کاربری فقط نشان می‌دهد.

## طبقه‌های شدت

بحرانی (Critical)، بالا (High)، متوسط (Medium)، پایین (Low)، اطلاعاتی (Informational): همان مدل داده‌ی فعلی (`Findings::SEVERITIES`).

## صفر، ناموجود، نامعتبر، ارزیابی‌نشده

| وضعیت | نمایش |
| --- | --- |
| صفر واقعی (اسکن کامل، چیزی پیدا نشد) | عدد ۰، کم‌رنگ؛ متن «این اسکن مشکلی پیدا نکرد» |
| ارزیابی‌نشده (هنوز اسکنی تمام نشده) | خط تیره (—) و «هنوز اسکنی تمام نشده است»؛ هرگز ۰ یا ۱۰۰ |
| ارزیابی ناقص (اسکنر مسدود شد یا مدرک اجرا نبود) | برچسب «ارزیابی ناقص» و دلیل؛ هرگز «سالم»؛ یافته‌های قبلی «رفع‌شده» نمی‌شوند |
| داده‌ی ناموجود (مثلاً CVSS یا EPSS ندارد) | ردیف نشان داده نمی‌شود (`Ui::facts` ردیف خالی را حذف می‌کند) |
| پایش: از همه‌جا / نه از همه‌جا / از دسترس خارج | سه وضعیت جدا با واژه |

## نمودارها

امروز: SVG سمت سرور (`Charts.php`). نگه داشته و استاندارد می‌شوند.

**Apache ECharts** (Apache-2.0) به‌عنوان گزینه‌ی نمودار پیشرفته بررسی می‌شود؛ به React نیاز ندارد. شرط‌های پذیرش:

- نیاز واقعی که SVG فعلی برنمی‌آورد (بزرگ‌نمایی، بازه‌ی دلخواه، tooltip روی هر نقطه، تعداد زیاد سری)
- نسخه‌ی رایگان و متن‌باز، مجوز همان نسخه بررسی‌شده
- فایل محلی در بسته، فقط در صفحه‌ای که لازم دارد، بی افزایش بی‌دلیل حجم
- سازگار با Lagom2، روشن و تیره، RTL و LTR
- جایگزین متنی یا جدولی برای داده‌ی اصلی؛ بی JavaScript همان SVG یا جدول دیده شود
- برچسب و tooltip فقط متن بگیرند (نه HTML)

کاربردهای ممکن: توزیع شدت، روند ریسک، تاریخچه‌ی وضعیت امنیتی، روند کشف دارایی و آسیب‌پذیری، پیشرفت رفع، تاریخچه‌ی اسکن، روند در معرض بودن، توزیع ریسک، سن آسیب‌پذیری‌ها، مقایسه‌ی ریسک دارایی‌ها.

نتیجه‌ی بررسی و نمونه‌ی آزمایشی: [MIGRATION_PLAN.md](MIGRATION_PLAN.md)، بخش ECharts.

## نقشه‌ی راه (فاز ۴؛ هر کدام با تأیید جدا)

رابطه‌ی دارایی‌ها و سطح حمله: گراف رابطه‌ی دارایی‌ها، رابطه‌ی دامنه و زیردامنه، رابطه‌ی IP و سرویس، نقشه‌ی وابستگی دارایی، نمایش در معرض بودن، نقشه‌ی سطح حمله، رابطه‌ی آسیب‌پذیری‌ها، توپولوژی شبکه.

گزینه‌های متن‌باز برای گراف تعاملی، به ترتیب سازگاری با معماری فعلی (اول آن‌هایی که بی React کار می‌کنند): Cytoscape.js، Apache ECharts Graph، Sigma.js، و React Flow Core (نیازمند React). معیار انتخاب: نوع گراف، شمار گره و یال، کارایی، نوع تعامل، مجوز. هیچ‌کدام نصب نشده است.

جدول پیشرفته (اسکرول مجازی، سنجاق ستون، سازنده‌ی فیلتر): اگر صفحه‌بندی سمت سرور فعلی کم آورد، جدا بررسی می‌شود.
