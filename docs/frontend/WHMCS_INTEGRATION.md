# یکپارچگی رابط کاربری با WHMCS و Lagom2

MC-Sec یک «Advanced Hybrid WHMCS Module» است: امروز تماماً **Maral Native WHMCS UI** (PHP، CSS، JavaScript ساده)، با امکان پذیرش کامپوننت‌های پیشرفته در آینده، هر کدام با تأیید جدا.

## مدل نمایش

| سطح | کجا | چطور ساخته می‌شود | هویت بصری |
| --- | --- | --- | --- |
| پنل امنیت مشتری | `index.php?m=mcsec` (خروجی `_clientarea`، قالب `templates/page`) | `lib/Client/*`، HTML سمت سرور | هماهنگ با Lagom2، با ظاهر تخصصی یک محصول امنیت |
| پنل مدیر | `addonmodules.php?module=mcsec` (خروجی `_output`) | `lib/Admin/*`، HTML سمت سرور | هویت MC-Care («style B») |
| صفحه‌های بی ورود | `p=scanner`، `p=check`، `p=shared`، `p=badge` | همان `lib/Client` | همان پنل مشتری، بی منو |

هر دو سطح از توکن‌ها و مفهوم‌های مشترک استفاده می‌کنند ([DESIGN_SYSTEM.md](DESIGN_SYSTEM.md))؛ مقدار رنگ‌ها و چیدمان هر کدام مال خودش است. ظاهر پنل مدیر به پنل مشتری تحمیل نمی‌شود و برعکس.

## جداسازی CSS و اسکریپت

- همه‌ی CSS ناحیه‌ی کاربری زیر `.mcs` و همه‌ی CSS پنل زیر `.mcsa` است. هیچ reset سراسری، هیچ انتخابگر بی این ریشه‌ها.
- فایل‌های قالب Lagom2 هرگز عوض نمی‌شوند. رنگ سطح‌ها از متغیرهای خود Lagom2 خوانده می‌شود (با مقدار پشتیبان برای بیرون از Lagom2).
- حالت تیره از کلاس `html.lagom-dark-mode` پیروی می‌کند.
- چیدمان با container query روی `.mcs-view` و `.mcs-main` است، نه عرض پنجره: داخل Lagom2 بخش ما از صفحه باریک‌تر است.
- CSS و JavaScript درون همان صفحه می‌آیند (بی درخواست جدا، بی CDN).
- JavaScript فقط بهبود تدریجی است؛ هر کار اصلی بی آن انجام می‌شود (`<details>` برای کشو و منو، فرم ساده برای هر کار).

## مدل امنیتی (دست‌نخورده می‌ماند)

- هویت فقط از نشست WHMCS (`Auth::client`)؛ هر شناسه‌ی مرورگر با حساب نشست سنجیده می‌شود.
- GET هرگز داده یا وضعیت را عوض نمی‌کند.
- هر POST ناحیه‌ی کاربری: توکن WHMCS + `mcs_csrf`؛ کار سازنده یا مصرف‌کننده‌ی اعتبار: nonce یک‌بارمصرف.
- هر POST پنل: `mcsa_csrf` و سطح نقش.
- مجوز، جداسازی حساب‌ها، سقف پلن و سهمیه در سمت سرور سنجیده می‌شوند؛ پنهان بودن یک دکمه مرز امنیتی نیست.
- هیچ رمز، کلید API یا توکن مدیریتی به مرورگر نمی‌رود.

اگر روزی جزیره‌ی React یا API مبتنی بر JSON تأیید شود، باید همین کنترل‌ها را کامل داشته باشد. هر تغییر در این مدل بررسی تخصصی و تأیید جدای بنیان‌گذار می‌خواهد.

## ساخت و انتشار

- امروز: بی مرحله‌ی ساخت. `php tools/release.php` پوشه‌ی `modules/` را zip می‌کند.
- اگر کتابخانه‌ای با نیاز به ساخت تأیید شد: Node.js فقط در توسعه و CI؛ سورس، تنظیم ساخت و lockfile در مخزن؛ خروجی ساخته‌شده در بسته‌ی انتشار؛ نصب روی WHMCS بی هیچ ابزار ساخت؛ راه برگشت به نسخه‌ی قبل. پیش از تغییر، همین سند و `tools/release.php` به‌روز می‌شوند.

## آزمودن روی محیط واقعی

پیش‌نمایش محلی (`tests/tools/preview.php`) قالب واقعی Lagom2 نیست: فقط چند متغیر آن را شبیه‌سازی می‌کند. هر مرحله باید روی staging واقعی دیده شود:

- نبودن برخورد CSS با قالب و ماژول‌های دیگر
- منوی قالب، عرض واقعی ستون محتوا، container query
- کشو، منو و فرم‌ها
- روشن و تیره، فارسی و انگلیسی، موبایل
- جدول‌های بلند، گزارش و PDF
- ورود، کاربر فقط‌دیدنی، ورود به‌جای مشتری

نتیجه‌ی آزمون محلی هرگز به‌عنوان «سازگاری با Lagom2 واقعی» گزارش نمی‌شود.
