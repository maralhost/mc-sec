# Maral Design System در MC-Sec

سه لایه‌ی استاندارد طراحی محصولات مارال کلاد:

| لایه | چیست | در MC-Sec |
| --- | --- | --- |
| **Maral Design System** | زبان طراحی مشترک: نام توکن‌ها، قرارداد کامپوننت‌ها، قاعده‌های نمایش | همین سند |
| **Maral Native WHMCS UI** | کامپوننت‌های PHP، CSS و JavaScript ساده | همه‌ی رابط کاربری امروز (`lib/Client`، `lib/Admin`) |
| **Maral Advanced UI** | کامپوننت‌های پیشرفته با React و کتابخانه‌های تخصصی | هنوز هیچ؛ هر مورد با نیاز واقعی و تأیید جدا |

MC-Sec یک «Advanced Hybrid WHMCS Module» است. هر ماژول مستقل نصب و اجرا می‌شود: توکن‌ها در خود هر ماژول تعریف می‌شوند (فایل مشترک میان ماژول‌ها نداریم) و فقط **نام‌ها** مشترک‌اند.

## دو سطح، یک زبان

| | پنل امنیت مشتری | پنل مدیر |
| --- | --- | --- |
| ریشه‌ی CSS | `.mcs` | `.mcsa` |
| هویت | هماهنگ با Lagom2؛ ظاهر تخصصی محصول امنیت | هویت MC-Care («style B») |
| رنگ سطح‌ها | از متغیرهای Lagom2 (با مقدار پشتیبان) | مقدار ثابت همان MC-Care |
| حالت تیره | دارد (از `html.lagom-dark-mode`) | ندارد (پنل مدیر WHMCS تیره نیست) |
| زبان | فارسی و انگلیسی، RTL و LTR | فقط فارسی |
| فایل | `lib/Client/client.css` | `Admin\Views::css()` |

نام توکن‌ها در هر دو یکی است (`--mds-*`)؛ مقدارها و چیدمان هر سطح مال خودش است.

## توکن‌ها

نام‌گذاری به واژگان shadcn/ui نزدیک است. پیشوند `--mds-` برای این است که با متغیرهای قالب میزبان یا ماژول دیگر برخورد نکند.

### عمومی (هر دو سطح)

| توکن | معنی |
| --- | --- |
| `--mds-background` | زمینه‌ی صفحه‌ی بخش |
| `--mds-foreground` | متن |
| `--mds-heading` | عنوان‌ها (پنل مشتری) |
| `--mds-surface`، `--mds-surface-sunken` | کارت و سطح؛ سطح فرورفته |
| `--mds-primary`، `--mds-primary-foreground`، `--mds-primary-soft` | کار اصلی و متن روی آن |
| `--mds-secondary`، `--mds-secondary-foreground` | سطح دوم (سربرگ جدول و کارت) |
| `--mds-muted`، `--mds-muted-foreground` | کم‌رنگ؛ متن کمکی |
| `--mds-accent`، `--mds-accent-soft` | تأکید (پنل مشتری) |
| `--mds-border`، `--mds-input`، `--mds-input-border` | مرز و فیلد |
| `--mds-ring` | حلقه‌ی فوکوس |

### امنیتی (جدا از رنگ‌های عمومی؛ پنل مشتری)

| گروه | توکن‌ها | برای چه |
| --- | --- | --- |
| شدت یافته | `--mds-sev-critical`، `-high`، `-medium`، `-low`، `-info` (هر کدام با `-bg` و `-fg`) | فقط شدت خود مشکل |
| امتیاز امنیت | `--mds-risk-strong`، `-good`، `-fair`، `-poor`، `-none` | حلقه‌ی امتیاز و رتبه؛ با شدت یکی نیست |
| وضعیت اسکن | `--mds-scan-queued`، `-running`، `-completed`، `-partial`، `-failed`، `-cancelled` | |
| وضعیت دارایی | `--mds-asset-verified`، `-pending`، `-lapsed`، `-removed` | |
| گواهی | `--mds-cert-expired`، `-month`، `-quarter`، `-long` | روزهای مانده |
| نمودار | `--mds-chart-1 … -6` | رنگ سری‌ها، به ترتیب |

تعریف‌ها: بالای `client.css` (بلوک «Maral Design System tokens») و ابتدای `Admin\Views::css()`.

### سازگاری با نام‌های قبلی

۳۱ توکن قبلی (`--t-*` و `--sev-*`) حذف نشده‌اند: همچنان به متغیرهای Lagom2 وصل‌اند و `--mds-*` روی آن‌ها سوار است. قاعده‌های قدیمی با همان نام‌ها کار می‌کنند؛ **قاعده‌ی تازه فقط `--mds-*` می‌نویسد**. در پنل مدیر نام‌های کوتاه (`--ink`، `--mu`، `--ln`، `--hd`، `--p`، `--g`، `--y`، `--r`) alias توکن‌های تازه‌اند؛ MC-Care هم همین نام‌های کوتاه را با همین مقدارها دارد.

### رنگ ثابت در کد

ممنوع است. آزمون `tests/ui_test.php` این‌ها را می‌سنجد: هیچ کد رنگ در PHP صفحه‌های مشتری، هیچ کد رنگ در قاعده‌های پنل مدیر پس از بلوک توکن، و سری نمودار با شماره‌ی توکن (نه رنگ).

استثناهای مستند:
- مسیر آیکون‌ها در `Ui::ICONS` (رنگ ندارند؛ `currentColor`).
- پیش‌نمایش لوگو در صفحه‌ی «قالب گزارش» روی رنگ جلد PDF (`#0b1f3a`): باید همان رنگ جلد باشد، نه رنگ پنل.
- نشان سایت (`Shares::badgeSvg`): یک تصویر مستقل است که در سایت مشتری نشان داده می‌شود و CSS ما را ندارد.
- قالب PDF: رنگ‌ها از تنظیم‌های مدیر می‌آیند (`Pdf::template`) و به حالت تیره‌ی مرورگر وابسته نیستند.
- قاعده‌های `.mcs-console` و `.mcs-radar` در `client.css`: مال داشبورد پیش از ۰٫۱۷٫۰ هستند و دیگر استفاده نمی‌شوند؛ نامزد حذف (با تأیید).

## حالت روشن و تیره

- پنل مشتری از Lagom2 پیروی می‌کند. هر توکن امنیتی در هر دو حالت مقدار دارد.
- آزمون خودکار کنتراست (axe-core) روی شش صفحه در چهار ترکیب زبان و حالت اجرا می‌شود.
- **یک مورد باز:** متن سفید روی رنگ اصلی در حالت تیره. در پیش‌نمایش محلی رنگ اصلی تیره یک آبی روشن فرضی است و کنتراست کم می‌آورد (۲٫۵). رنگ واقعی را Lagom2 تعیین می‌کند؛ باید روی staging دیده شود و اگر لازم بود `--mds-primary-foreground` در حالت تیره عوض شود.

## جهت و زبان

- فقط ویژگی‌های منطقی CSS (`margin-inline-start`، `inset-inline-end`، …).
- مقدار فنی (IP، دامنه، URL، CVE، CVSS، درگاه، هش، خروجی دستور) همیشه چپ‌به‌راست و جدا از متن (`Ui::ltr`، `Ui::code`).
- رقم و تاریخ از زبان پیروی می‌کنند (`Text::fa`، `Text::date`): فارسی با رقم فارسی و تاریخ شمسی؛ انگلیسی با رقم لاتین و تاریخ میلادی.
- محور زمان نمودارها در فارسی از راست به چپ است (`Charts::$rtl`)؛ نقشه همیشه غرب در چپ.
- ترجمه با سازوکار خود پروژه (`Lang`، `lang/en/`)؛ کتابخانه‌ی ترجمه لازم نیست. `php tools/i18n.php` پس از هر مرحله.

## گزارش PDF

قالب PDF مستقل از مرورگر است: رنگ، فونت و بخش‌ها از تنظیم‌های گروه `report` می‌آیند (`Pdf::template`)، مناسب چاپ، بی وابستگی به حالت تیره. عددهای گزارش همان عددهای Backend و داشبورد است (از `Reports::compose`). موتور PDF و محتوای گزارش در این مرحله عوض نشده‌اند.
