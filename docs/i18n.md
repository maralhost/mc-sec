# MC-Sec in two languages (Persian and English)

Since 0.13.0 everything a **customer** sees is Persian or English. The admin panel stays Persian.

## How it works

- The module is written in Persian. **The Persian text is the key.** `modules/addons/mcsec/lang/en/*.php` hold the
  English: each file returns `[Persian => English]`, and `McSec\Lang` merges them all.
- `Lang::t('… {n} …', ['n' => $x])` returns the text in the current language and fills `{placeholders}`.
  In Persian it is the Persian text itself; in English the dictionary's value; a text with no English yet is shown in
  Persian (never empty, never a key).
- `Text::e()` (so `Ui::e()`, `self::e()` and every block that escapes a label: `Ui::card` titles, `Ui::chip`,
  `Ui::td` labels, table heads, select options, `Ui::flash` lines …) translates **a whole string that is a dictionary
  key** by itself. So a label that comes from a constant (`Findings::SEVERITIES[$k]['label']`, `Scans::STATUS`, …) or a
  plain message (`'err:این دارایی پیدا نشد.'`, `['error' => '…']`) needs **no code change**, only a dictionary entry.
- `Text::fa($n)` gives Persian digits in Persian and leaves Latin digits in English; `Text::num`, `Text::money`,
  `Text::date`, `Text::ymd`, `Text::ago` follow the language (Gregorian dates in English). Keep calling them.
- `Lang::fa()` is true in Persian; `Lang::join($items)` joins a list with `، ` or `, `; `Lang::attrs()` gives
  `dir="…" lang="…"` for a root element; `Lang::dir()` gives `rtl` / `ltr`.
- Which language: the visitor's WHMCS language in the client area; **the account's own language** for background work
  (`Lang::with(Lang::forClient($clientId), fn () => …)`: notices, e-mails, reports, findings written by a scan).
  `farsi` is Persian, every other WHMCS language gets English.

## Rules for code

1. **A sentence built from pieces becomes one `Lang::t()` with placeholders.** Not
   `Text::fa($n) . ' دارایی افزوده شد'` but `Lang::t('{n} دارایی افزوده شد', ['n' => Text::fa($n)])`. Each language
   needs its own word order, so never translate fragments like `' از '`, `' و '`, `' روی '` on their own.
   Values that are HTML go in as they are (`['asset' => Ui::ltr($a->value)]`) when the result is used as HTML; when the
   result goes through `e()`, pass plain values.
2. **Persian inside an HTML literal** (`'<p>متن</p>'`) is not escaped by `e()`, so wrap the text:
   `'<p>' . Lang::t('متن') . '</p>'`, or keep small inline markup inside the key:
   `Lang::t('<strong>ارزیابی ناقص.</strong> این اسکن «سالم» به حساب نمی‌آید.')` (the English value then carries the
   same markup).
3. **A whole plain string that reaches the page through `e()`** stays as it is in the code; add it to the dictionary.
   This covers constants (labels, statuses), `['error' => '…']` results and `'ok:…'` / `'err:…'` flash messages
   (the key is the text after `ok:` / `err:`; a flash with several lines is translated line by line).
   A flash or error built from pieces follows rule 1: `'err:' . Lang::t('…{x}…', […])`.
4. Persian punctuation that joins values in code (`'، '`, `' · '`, `'؛ '`, `'٪'`, `'«' . $x . '»'`) goes inside the
   translated sentence or through `Lang::join()`. English uses `, ` `;` `%` and "quotes".
5. **Not for customers, so not translated** (leave Persian, and put the comment `// i18n-skip` at the end of the line,
   or `// i18n-skip-begin` … `// i18n-skip-end` around a block): messages for the scan journal (`ScanLog::…`), the
   technical log (`Trace::…`), admin alerts, anything only the admin panel shows, prompts sent to the model, and
   character tables (digits, letters). When in doubt whether a customer can see a text: they can, translate it.
6. Never change behaviour, HTML structure, CSS classes, array keys, test-visible Persian output, or the Persian
   text itself (the tests assert it). In Persian the page must be byte-for-byte what it was.
7. Technical tokens stay as they are in both languages: domains, IPs, ports, CVE ids, tool names (Nuclei, ZAP, OASM),
   config snippets and commands.

## English style

Plain, short, friendly English for site owners who are not security experts; sentence case; no exclamation marks.
Glossary: دارایی = asset · تأیید مالکیت = ownership verification / verify ownership · یافته = finding ·
اسکن = scan · اعتبار = credit(s) · بسته = pack · پلن = plan · سطح حمله = attack surface · زمان‌بندی = schedule ·
اعلان = notification · خبر = notice · ارزیابی ناقص = incomplete assessment · بحرانی/بالا/متوسط/پایین/اطلاعاتی =
Critical/High/Medium/Low/Info · رفع‌شده = fixed · پذیرفته‌شده = accepted · مثبت کاذب = false positive ·
دستیار امنیت = Security assistant · کمک کارشناس = Expert help · مارال کلاد = Maral Cloud · بله = Bale (the messenger) ·
ناحیه‌ی کاربری = client area · پشتیبانی = support · کد پیگیری = tracking code · امتیاز امنیت = security score.

## Checking

`php tools/i18n.php` lists every Persian literal of a customer-facing file that has no English, translations that
still contain Persian letters, and placeholders that differ. `php tools/i18n.php lib/Scans.php` checks one file.
`bash tests/run.sh` must stay green (Persian output unchanged); `tests/i18n_test.php` renders every page in English.
Preview: `http://127.0.0.1:8796/index.php?m=mcsec&lang=en` (and `&lang=fa` to go back).
