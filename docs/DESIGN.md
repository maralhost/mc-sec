# MC-Sec — طرح محصول و فنی (نسخه‌ی ۰٫۱٫۰، ۲۰ آبان ۱۴۰۵)

> فضای کار امنیت سایبری مشتریان مارال کلاد، درون ناحیه‌ی کاربری WHMCS. این سند جمع‌بندی طوفان فکری، بررسی رقبا، طراحی تجربه و معماری است و تصمیم‌های باز برای بنیان‌گذار را جدا می‌گوید. پژوهش‌های کامل: `docs/research/` (رقبا، UI/UX، OASM، Osmedeus).

## ۱. مسئله و مخاطب
- **مشتری اصلی:** صاحب کسب‌وکار کوچک و متوسط با سایت (اغلب وردپرس/ووکامرس) روی هاست یا سرور مارال؛ متخصص امنیت نیست، می‌خواهد بداند «وضعم چطور است و الان چه کنم».
- **مشتری فنی:** devops یا آژانسی که ده‌ها دامنه و سرور دارد؛ فهرست، زمان‌بندی، وب‌هوک و گزارش برای کارفرما می‌خواهد.
- **چرا مارال:** مارک «مشاور، نه فقط سرویس‌دهنده». در ایران سرویس SaaS فارسی و خودکار ارزیابی امنیتی نیست (رقبای خارجی عملاً در دسترس نیستند؛ گزینه‌های داخلی خدمت دستی ۸ تا ۴۰ میلیون تومانی یا باگ‌بانتی‌اند). مارال تنها جایی است که مالکیت را بی‌گام اضافه می‌داند (دامنه و سرور در همان WHMCS).

## ۳. آنچه از رقبا آموختیم (خلاصه؛ کامل در `research/competitive-analysis.md`)
1. قیمت‌گذاری رایج به ازای دارایی/هدف است، نه هر اسکن؛ مدل اعتباری در حال رشد است (Snyk ۳ اعتبار در روز برای هر هدف).
2. «کشف رایگان، اسکن اعتباری» بهترین قیف است.
3. DAST‌ها مالکیت را با DNS/فایل/متا می‌سنجند؛ محصولات میزبان آن را ضمنی می‌دانند ← ما هر دو.
4. هوش مصنوعی در رقبای جدی استاندارد شده؛ هیچ‌کدام فارسی یا محلی نیست.
5. تمایز اصلی: اسکن تهدیدهای نوظهور و هشدار «چه چیزی تغییر کرد».
6. ریسک اصلی مشتری میزبانی وردپرس است (بیشتر آسیب‌پذیری‌ها در افزونه‌ها).
7. افزونه‌های امنیتی میزبان‌ها ۲ تا ۸ دلار برای هر سایت در ماه‌اند.
8. یکپارچگی SiteLock با WHMCS (فعال‌سازی خودکار، ورود یکپارچه) الگوست.
9. در ایران رقیب SaaS فارسی نیست.
10. اسکن درگاه روی IP میزبانی اشتراکی و CDN ممنوع؛ IP اسکنرها در فایروال‌های مارال allowlist شود.

## ۴. جریان‌ها
**مشتری:** منوی «امنیت سایبری» ← نمای کلی (چک‌لیست شروع) ← افزودن دارایی (یک کادر؛ «پس از تأیید خودکار اسکن کن») ← تأیید (خودکار برای سرویس‌های مارال؛ وگرنه TXT روی `_mcsec-verify` یا فایل یا متا با دکمه‌ی «الان بررسی کن» و پیگیری خودکار تا ۷ روز) ← اسکن (کارت‌های نوع اسکن با هزینه و زمان؛ دکمه‌ی «شروع اسکن · N اعتبار» و مانده‌ی پس از آن) ← پیشرفت زنده ← یافته‌ها (از مهم‌ترین؛ هر کدام: چیست، چرا مهم است، گام‌ها، کد، راهکار هوش مصنوعی، رفع کردم/پذیرش ریسک/مثبت کاذب) ← گزارش (پایه خودکار؛ هوش مصنوعی با اعتبار؛ چاپ/PDF) ← زمان‌بندی ← اعلان‌ها (پنل، ایمیل، بله/تلگرام با کد، وب‌هوک امضاشده؛ ماتریس رویداد×کانال؛ گزارش هفتگی/ماهانه) ← اعتبار و پلن (مانده‌ی دو بخشی، هزینه‌ها، خرید بسته با فاکتور WHMCS، تراکنش‌ها).
**مدیر:** راه‌اندازی موتورها (OASM، Osmedeus، هوش مصنوعی، ربات‌ها؛ هر کدام «آزمودن») ← قیمت و پلن (نوع‌های اسکن، بسته‌ها، محصول‌های `mcsecplan`) ← اعتبار رایگان گروه‌ها و اعطای تکی ← دارایی‌ها و تأیید دستی ← صف اسکن (توقف/دوباره) ← تنظیمات (دسترسی آزمایشی، فهرست ممنوع، ظرفیت، کلید اضطراری) ← گزارش فنی با کد پیگیری.
جزئیات گام‌به‌گام و نقطه‌های اصطکاک: `.claude/skills/mcsec-ideation/references/flows.md`.

## ۵. معماری (خلاصه؛ کامل در اسکیل `mcsec-architect`)
- افزونه‌ی `modules/addons/mcsec` (PHP 8.3، بدون Composer/CDN) + ماژول سرور `modules/servers/mcsecplan` برای پلن‌ها.
- HTML سروری با pjax؛ هر صفحه بی JavaScript کار می‌کند؛ CSS محدود به `.mcs` روی متغیرهای Lagom2 (حالت تیره خودکار).
- موتورها پشت رابط `Engine` (Builtin، OASM، Osmedeus) با خروجی نرمال؛ ارکستریتور `Scans` با صف، سقف همزمانی، poll، collect و بازگشت اعتبار؛ کار پس‌زمینه از cron خود WHMCS با قفل.
- OASM: برای هر حساب یک کاربر و یک فضای کار (محدودیت ۵ فضا برای هر کاربر)؛ Osmedeus: یک workspace برای هر دارایی (`space_name`).
- یافته‌ها با اثرانگشت یکتا و چرخه‌ی عمر؛ «رفع خودکار» فقط به دست همان نوع اسکن.
- ۲۳ جدول `mod_mcsec_*`، همه افزودنی. هیچ نوشتنی در `tbl*` جز `SendEmail` و `CreateInvoice`.

## ۶. قیمت‌گذاری (پیش‌فرض‌های کد؛ همه از پنل قابل تغییر)
- **اعتبار هر اسکن برای هر دارایی:** سلامت پایه ۰، کشف سطح حمله ۲، آسیب‌پذیری ۶، شناسایی سریع ۸، ارزیابی عمیق ۳۰ (فقط پلن)، گزارش هوش مصنوعی ۲.
- **بی‌پلن:** ۳ دارایی، زمان‌بندی حداکثر هفتگی، ۱۰ اعتبار خوش‌آمد.
- **پیشنهاد پلن‌ها (از پژوهش رقبا):** Starter ۳ دارایی/۱۵۰ اعتبار ماهانه؛ Pro ۱۰/۶۰۰ و روزانه؛ Business ۳۰/۲۰۰۰؛ Agency ۱۰۰/۶۰۰۰. قیمت Starter حدود معادل ۴ تا ۶ دلار، سالانه = ۱۰ ماه.
- **بسته‌ها:** ۵۰، ۲۰۰، ۱۰۰۰ اعتبار با تخفیف پلکانی؛ هر اعتبار دست‌کم ۳ برابر هزینه‌ی تمام‌شده.
- **اعتبار رایگان گروه‌ها:** برای هر گروه WHMCS اعتبار ماهانه و سقف دارایی (مثلاً همکاران ۱۰۰، VIP ۵۰).

## ۷. امنیت و قانون اسکن
تأیید مالکیت پیش از هر اسکن؛ ارث فقط از تأیید سطح DNS؛ درگاه فقط روی IP مال مشتری؛ IP خصوصی ممنوع؛ فهرست ممنوع (gov/mil/sch.ir)؛ متن رضایت با ثبت زمان و کاربر؛ کلید اضطراری `scans_paused`؛ گارد SSRF برای هر URL مشتری؛ رمزها رمزنگاری‌شده؛ داده‌ی اسکن پیش از رفتن به مدل ماسک می‌شود و «داده» است نه دستور. قواعد کامل: اسکیل `cybersec-expert` و `references/rules-of-engagement.md`.

## ۸. تصمیم‌های باز برای بنیان‌گذار
1. **سقف امتیاز با یافته‌ی «بالا»:** کد ۷۹؛ پژوهش UX ۷۴ پیشنهاد داده. کدام؟
2. **قیمت‌ها:** اعداد پلن‌ها و بسته‌ها (ریال) و هزینه‌ی هر نوع اسکن.
3. **متن رضایت اسکن و شرایط استفاده:** بازبینی حقوقی (قانون جرایم رایانه‌ای).
4. **هوش مصنوعی:** کدام سرویس (OpenAI مستقیم، New API مارال یا درگاه داخلی)؛ و پذیرفتنی بودن فرستادن داده‌ی یافته‌ها (ماسک‌شده) به سرویس بیرونی.
5. **کانال پیام‌رسان:** بله اصلی، تلگرام هم؟ (از سرورهای داخل ایران `api.telegram.org` ممکن است در دسترس نباشد.)
6. **ارزیابی عمیق (Osmedeus general):** پیش از روشن کردن برای مشتری، دامنه‌ی ماژول‌های آن (اسکن درگاه زیردامنه‌ها) بازبینی شود.
7. **نام منو:** «امنیت سایبری» یا «امنیت سایت».

## ۹. وضعیت آزمون (۰٫۱٫۰)
- ۳۲۵ بررسی خودکار در ۶ مجموعه سبز (`bash tests/run.sh`): واحدها، اعتبار، جریان کامل، موتورها با پاسخ‌های شبیه‌سازی‌شده، امنیت (IDOR، CSRF، nonce، XSS، مجوز، سطح مدیر، رمز)، رندر همه‌ی صفحه‌ها.
- **OASM:** endpointها و احراز هویت روی staging (v0.12.1) زنده آزموده شد (ورود، فهرست هدف، اجراها، دارایی‌ها). ساختن کاربر و فضا و اسکن واقعی از WHMCS هنوز آزموده نشده.
- **Osmedeus:** از این محل در دسترس نبود (اتصال TCP بسته؛ احتمالاً allowlist)؛ اتصال از روی سورس v5 ساخته و با پاسخ شبیه‌سازی آزموده شد.

## ۱۰. چک‌لیست staging
- [ ] زیپ `php tools/release.php` را روی WHMCS staging باز کنید؛ Addon Modules › MC-Sec › Activate؛ Access Control نقش‌ها.
- [ ] صفحه‌ی ماژول را باز کنید (نصب جدول‌ها)؛ «راه‌اندازی موتورها»: OASM (کاربر admin مخصوص WHMCS)، Osmedeus (کلید API؛ فایروال IP سرور WHMCS را بپذیرد)، هوش مصنوعی، ربات بله؛ هر کدام «آزمودن».
- [ ] `php tools/selftest.php /path/to/whmcs` روی سرور WHMCS.
- [ ] تنظیمات: `enabled=1`، `access_mode=list` با دو حساب آزمایشی؛ اعتبار رایگان گروه آزمایشی.
- [ ] با حساب آزمایشی: افزودن دامنه‌ای که در همان حساب است (تأیید خودکار)، دامنه‌ی بیرونی با TXT، IP سرور؛ اسکن هر نوع؛ مقایسه با پنل OASM/Osmedeus.
- [ ] خرید بسته (فاکتور ← پرداخت با اعتبار حساب ← اعتبار اسکن)؛ محصول پلن با `mcsecplan` ← سفارش ← CreateAccount ← اعتبار ماهانه.
- [ ] اعلان‌ها: ایمیل، اتصال بله با کد، وب‌هوک (امضای HMAC).
- [ ] حالت تیره‌ی Lagom2، گوشی، «ورود به‌جای مشتری» (فقط دیدن)، کاربر غیرمالک با مجوز products.
- [ ] فایروال/WAF خود مارال: IP اسکنرها allowlist.
